Paid music routes accept a USDC session or Credits. Both use the selected account address. [Request setup](/dev/guides/connect) defines the shared client.

## Pay with a USDC session

Open **SESSION** in [Rawchunks](https://app.rawchunks.space), choose **USDC**, set a cap and duration, then start the session. Follow the [session walkthrough](/app/payments#start-a-session).

Send the complete issued token as `Authorization: Bearer $SESSION_TOKEN`, with `x-session-user-address` and `x-network-id`. The **Copy Key ID** action copies an identifier. To obtain the full token, inspect an authenticated Rawchunks request in your browser's Network panel and copy its Authorization bearer value.

The cap authorizes spending until expiration or revocation. Keep the token in secret configuration.

## Pay with Credits

Send these headers instead of the USDC funding headers:

| Header | Value |
| --- | --- |
| `x-session-user-address` | Selected wallet address. |
| `x-wallet-auth-token` | Embedded wallet's authentication token. |
| `x-credit-source` | `card` for purchased Credits or `promo` for campaign Credits. |
| `x-idempotency-key` | A stable operation key of at most 80 characters for a paid service. |

Credits account and checkout routes resolve ownership from wallet authentication or an authenticated USDC session. The campaign claim requires wallet authentication. Checkout creation and campaign claims require idempotency keys of 8 to 128 characters.

Reuse a key for the same operation. An already admitted service can return 409; recover its saved IDs before submitting again. [Job handling](/dev/guides/jobs).

## Read the balance

`GET /api/credits/balance` returns `availableAtomics`, `reservedAtomics`, `spentAtomics`, `suspendedAtomics` for purchased Credits, and a separate `promo` object with its allocation and available, reserved and spent amounts. It also returns packs, public checkout client ID and environment.

One Credit represents $0.01. Convert atomic amounts for display; keep integer strings for payment calculations.

## Prices

| Operation | USD / USDC | Credits |
| --- | ---: | ---: |
| Songwriter / Vibe | 0.03 | 3 |
| Fast generation | 0.05 | 5 |
| Master generation | 0.10 | 10 |
| Rework, layer, accompany, extend, restyle, extract, slice or separate | 0.02 | 2 |
| Save or upload a voice | 0.05 | 5 |

| Pack | Price | Credits |
| --- | ---: | ---: |
| `usd-10` | $10 | 1,000 |
| `usd-25` | $25 | 2,500 |
| `usd-100` | $100 | 10,000 |

The campaign offers 100 Credits to the first 1,000 eligible accounts. Promo Credits fund creation and editing. Purchased Credits or USDC fund listening; license checkout follows its own payment flow.

## Checkout and playback

[Create a Credits order](/dev/endpoints/credits/create-order), complete provider approval, then [capture it](/dev/endpoints/credits/capture-order). Read the balance after `credited`. Keep the operation ID for [status recovery](/dev/endpoints/credits/operation).

[License checkout](/dev/endpoints/credits/license-create) accepts caller-supplied atomic amounts and supports Base Sepolia, Tempo Moderato and Solana devnet. Amounts round to cents. Onchain licensing is covered in the [license guide](/dev/guides/publish/licenses).

Paid listening starts at the [stream endpoint](/dev/endpoints/library/stream). Save its payment intent and send cumulative listened time to [checkpoints](/dev/endpoints/library/checkpoint).

## Track or end a session

USDC responses include `x-session-budget-limit`, `x-session-budget-used` and `x-session-budget-remaining` in atomic units. Reopen **SESSION** to refresh status or **END SESSION** to revoke the key. Credits responses can include `x-credit-hold-id`; balances use the balance endpoint.
